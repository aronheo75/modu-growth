모두의 성장 2.4 통합본 - GitHub 한 번에 업로드 안내

이 패키지는 홈페이지 전체 파일을 한 폴더에 모은 통합본입니다.
기존 저장소의 파일을 하나씩 교체하지 않고, 이 폴더의 전체 파일을 main 브랜치 루트에 한꺼번에 업로드할 수 있습니다.

[업로드 전]
1. ZIP을 압축 해제합니다.
2. 압축 해제 폴더 안의 모든 파일을 확인합니다.
3. 현재 GitHub 저장소의 main 브랜치 파일을 ZIP 밖으로 별도 백업해 두는 것을 권장합니다.

[GitHub 업로드]
1. GitHub 저장소 modu-growth의 main 브랜치 루트로 이동합니다.
2. Add file > Upload files를 선택합니다.
3. 압축 해제 폴더 안의 모든 파일을 한꺼번에 선택해 업로드 영역에 끌어 놓습니다.
4. 같은 이름의 파일은 교체하고, 새 파일은 추가합니다.
5. 특히 config.js도 이 통합본에 포함되어 있습니다. 이 파일은 현재 사용 중인 Supabase 프로젝트 URL과 publishable key를 담은 기존 설정본입니다. service_role/secret key는 포함하지 않습니다.
6. Commit changes를 눌러 저장합니다.

GitHub 웹 업로드에서는 같은 이름 파일은 덮어쓰기되고, 패키지에 없는 기존 파일은 자동 삭제되지 않습니다.
불필요한 옛 SQL 파일을 삭제하고 싶다면 웹사이트가 정상 작동하는 것을 확인한 뒤 별도로 정리하세요. 전체 저장소를 먼저 비우는 방식은 권장하지 않습니다.

[Supabase 적용]
- supabase-company-profile-migration.sql: 기업회원 사업자정보 컬럼 추가용. 이미 2.3에서 성공적으로 실행한 경우 다시 실행하지 마세요.
- supabase-product-registration-migration.sql: 2.4 상품·서비스 영업정보 컬럼 추가용. 백업 후 SQL 내용을 확인하고, 아직 실행하지 않은 경우에만 새 SQL Editor 쿼리에서 한 번 실행합니다.
- supabase-company-library-migration.sql: 회사 자료실 전용 마이그레이션. 자료실을 아직 설정하지 않은 경우에만 별도 검토 후 실행합니다.
- supabase-schema-reference-do-not-run.sql: 참고용 전체 스키마. 실행 금지.

절대로 전체 스키마 SQL을 다시 실행하지 마세요. 기존 회원/로그인/상품 데이터의 삭제나 초기화를 하지 않습니다.

[배포 후 확인]
1. GitHub Pages 배포 완료를 확인합니다.
2. 홈페이지에서 Ctrl+F5로 강력 새로고침합니다.
3. 기존 기업회원 계정으로 로그인합니다.
4. 내 정보 화면에서 기존 사업자정보가 유지되는지 확인합니다.
5. 상품·서비스 등록 화면에서 수익모델, 가격방식, 주요 고객층, 공급지역, 핵심 경쟁력 항목을 확인합니다.
6. 상품 등록 테스트는 상품용 추가 SQL 적용 여부를 확인한 뒤 진행합니다.

주의: config.js에는 브라우저 공개용 publishable/anon key만 사용합니다. service_role 또는 secret key를 절대 넣지 마세요.
