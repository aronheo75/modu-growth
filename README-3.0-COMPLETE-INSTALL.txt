모두의 성장 3.0 전체 통합 업데이트

[목표]
기존 2.5 홈페이지 기능을 유지하면서 기업회원 + 비즈니스 파트너 + 관리자 기능을 통합 업데이트합니다.

[GitHub 적용]
1. 먼저 현재 GitHub 저장소를 백업합니다.
2. 이 ZIP의 압축을 풉니다. 파일은 별도 하위 폴더가 아닌 저장소 루트에 바로 들어 있습니다.
3. 압축을 푼 파일 전체를 기존 GitHub 저장소 최상위 폴더에 업로드합니다.
4. 같은 이름의 파일은 교체하고, 이 ZIP에 없는 기존 파일은 삭제하지 않습니다.
5. config.js가 ZIP에 포함되어 있습니다. 현재 GitHub의 config.js가 아래와 같은 기존 Supabase 프로젝트 설정인지 확인하고, 값이 다르면 GitHub의 최신 설정을 유지하세요. service_role/secret key는 절대 사용하지 마세요.

[포함 기능]
- 기존 로그인/회원가입, 기업 프로필, 상품 등록, 회사 자료실 및 2.5 관리자 상품 승인 기능
- 기업 상품별 제휴/협약 신청 및 상태 조회
- 기업의 총 영업 수수료율 제안, 관리자 파트너 지급률/플랫폼 운영률 배분
- 비즈니스 파트너 프로필, 승인 상품 탐색, 영업 참여 신청, 고객/영업건 등록
- 관리자 제휴 검토, 파트너 참여 승인, 실적 및 수동 정산 상태 관리

[Supabase SQL 주의]
SQL 파일은 여러 개가 함께 들어 있습니다. 이것들은 설치 순서와 적용 여부를 확인하기 위한 파일 묶음이며, 모두 무조건 다시 실행하라는 뜻이 아닙니다.
- supabase-schema-reference-do-not-run.sql: 참고용. 실행 금지.
- supabase-company-profile-migration.sql: 2.3 기업정보 확장. 이미 적용했다면 재실행하지 않아도 됩니다.
- supabase-company-library-migration.sql: 2.2 회사 자료실. 이미 적용했다면 재실행하지 않아도 됩니다.
- supabase-product-admin-migration.sql: 2.5 상품 확장 및 관리자 승인 보호. 적용 여부 확인 후 진행합니다.
- supabase-modoo-growth-3.0-migration.sql: 3.0 제휴/파트너/영업/정산 추가 기능. 기존 2.x 기반 구조가 준비된 후 실행합니다.
실행 전 Supabase 백업을 권장합니다. 오류가 나면 재실행·초기화·테이블 삭제를 하지 말고 오류 화면을 공유하세요.

[보안 및 운영]
관리자 role은 신뢰된 관리자 절차로만 부여해야 합니다. 일반 회원가입에서 관리자 역할을 선택할 수 없습니다. 실제 송금/PG 결제는 연결되어 있지 않으며 정산 상태를 기록하고 관리자가 수동 확인하는 기능입니다.
