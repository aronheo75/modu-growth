# 모두의 성장 2.0 | 전체 통합 배포 패키지

## 1. 이번 버전의 방향
- 메인 화면을 딥 네이비·라임 포인트의 프리미엄 비즈니스 플랫폼 디자인으로 전면 개편
- PC·태블릿·모바일 반응형 레이아웃
- 플랫폼 소개, 이용 방법, 핵심 서비스, 1차 모집 목표, 회원 유형별 안내, 회사 소개를 한 흐름으로 재구성
- 기존 Supabase 프로젝트 연결값과 기본 회원 인증 흐름 유지
- 로그인 회원의 본인 프로필 조회·수정, 기업회원의 본인 상품·서비스 등록 및 조회
- 기존 데이터베이스의 다른 회원 정보 전체를 브라우저에서 무단 조회하지 않도록 기존 코드의 전체 프로필 조회 제거

## 2. 배포 파일
- `index.html` : 전체 화면 구조 및 콘텐츠
- `style.css` : 2.0 전면 디자인 및 반응형 스타일
- `app.js` : 로그인·회원가입·프로필·기업 상품 등록
- `config.js` : 기존 Supabase URL 및 publishable key (기존 값 보존)
- `config.example.js` : 설정 예시
- `supabase-schema-reference-do-not-run.sql` : 기존 데이터베이스 구조 참고용. 실행 금지
- `GITHUB_UPLOAD_GUIDE.txt` : 통합 교체 안내

## 3. 기존 Supabase 보호
- 기존 Supabase 프로젝트와 회원 데이터는 변경하지 않습니다.
- `config.js`는 기존 프로젝트 URL 및 publishable key를 그대로 유지했습니다.
- service_role/secret key는 사용하지 않습니다.
- SQL 파일은 참고용이며 다시 실행하지 마세요. 기존 테이블·정책·트리거를 삭제하거나 재생성하는 작업은 포함하지 않습니다.

## 4. 현재 구현 범위 및 주의사항
실제 구현: Supabase 이메일 회원가입/로그인, 본인 프로필 조회 및 수정, 기업회원 본인 상품·서비스 등록/조회, 로그아웃.

아직 운영 기능으로 완성되지 않은 영역: 기업/파트너 간 실제 매칭, 거래·주문, 수수료·정산, 관리자 승인, 안전한 기업자료 업로드/다운로드, Storage 접근권한, AI 추천. 화면에서 해당 기능을 이미 제공한다고 오인하지 않도록 소개 콘텐츠는 플랫폼의 방향과 단계적 확장 계획으로 표현했습니다.

파트너의 전체 상품 탐색 기능은 현재 운영 DB의 `offers` RLS 정책을 확인하지 않고 임의로 노출하지 않습니다. 관리자 권한은 브라우저에서 부여하지 않습니다.

## 5. 배포 전 체크리스트
1. 현재 GitHub 저장소를 ZIP으로 백업합니다.
2. 이 패키지의 파일 전체를 기존 저장소 루트에 업로드해 같은 이름의 파일을 교체합니다.
3. `config.js`를 별도 편집하거나 `config.example.js`로 덮어쓰지 않습니다.
4. GitHub Pages 배포가 끝난 뒤 PC에서 Ctrl+F5, 모바일에서 새로고침합니다.
5. 회원가입/로그인, 프로필 수정, 기업 상품 등록은 테스트 계정으로 확인합니다.
6. 기존 RLS 정책에 따라 특정 기능이 거부되면 SQL을 즉시 실행하지 말고 오류 메시지와 정책을 먼저 검토합니다.

## 6. 검증 범위
패키지 구조, HTML 구문 파싱, JavaScript 구문, ZIP 무결성 등 정적 검증을 수행합니다. 실제 사용자의 Supabase 계정으로 로그인하거나 운영 DB에 쓰기 테스트를 수행한 것은 아닙니다.
